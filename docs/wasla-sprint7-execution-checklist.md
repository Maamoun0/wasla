## 🧩 القطعة 3 — طابور مراجعة الإعلانات

### 3.1 جلب الإعلانات المعلَّقة مرتبة بـ ai_risk_level
```
🔹 النوع: كود
🔹 المدخلات: عمودا ai_risk_level وai_review_notes من السبرنت 3
🔹 داخل النطاق: قائمة إعلانات بحالة pending مرتبة: high أولاً ← medium ← low + ترقيم صفحات
🔹 دليل الإثبات: قاعدة بيانات تحتوي إعلانات بمستويات مختلفة → التأكد أن high يظهر أعلى القائمة فعلاً
🔹 فحصك المباشر: إدراج 3 إعلانات تجريبية بمستويات مختلفة مباشرة في قاعدة البيانات ومراقبة الترتيب
```

### 3.2 شاشة تفاصيل الإعلان للمراجعة
```
🔹 النوع: كود
🔹 داخل النطاق: عرض كل تفاصيل الإعلان + ai_review_notes واضحة بصرياً + زرا قبول/رفض
🔹 خارج النطاق: لا تعديل على بيانات الإعلان من لوحة الإدارة — قبول أو رفض فقط
🔹 دليل الإثبات: عرض إعلان تجريبي بـ ai_risk_level = high ومراجعة أن ai_review_notes تظهر بوضوح
```

### 3.3 منطق القبول
```
🔹 النوع: كود
🔹 داخل النطاق: تغيير status إلى active + تسجيل في Audit Log (مَن قبل، متى، أي إعلان)
🔹 دليل الإثبات: قبول إعلان تجريبي → فحص جدول Audit Log مباشرة
🔹 فحصك المباشر: التأكد أن صف Audit Log يحتوي user_id المشرف الصحيح، لا null أو قيمة خاطئة
```

### 3.4 منطق الرفض (مع سبب من قائمة موحَّدة)
```
🔹 النوع: كود
🔹 المدخلات: قائمة أسباب الرفض من wasla-legal-policies.md
🔹 داخل النطاق: تغيير status إلى rejected + حفظ السبب + تسجيل Audit Log
🔹 المُخرَج المطلوب: سبب الرفض يظهر للمعلن في تطبيق Flutter عند رؤية حالة إعلانه (مربوط بـ FR-54 لاحقاً في الإشعارات)
🔹 دليل الإثبات: رفض إعلان تجريبي + فتح تطبيق Flutter بنفس الحساب → حالة "مرفوض" مع السبب واضحة
🔹 فحصك المباشر: التحقق من ظهور السبب بالضبط كما اختاره المشرف، لا رسالة عامة
```

## 🧩 القطعة 4 — طابور مراجعة التحقق من الهوية (KYC)

### 4.1 قائمة طلبات التحقق المعلَّقة
```
🔹 النوع: كود
🔹 داخل النطاق: قائمة طلبات بحالة pending مرتبة بالأقدم أولاً (FIFO)
🔹 دليل الإثبات: طلبان تجريبيان بأوقات مختلفة → الأقدم يظهر أولاً فعلاً
```

### 4.2 عرض وثيقة الهوية بـ Signed URL (5 دقائق فقط)
```
🔹 النوع: كود
🔹 المدخلات: دالة توليد Signed URL من القطعة 1.2 في السبرنت 4
🔹 داخل النطاق: زر "عرض الوثيقة" يُولِّد Signed URL في اللحظة ويسجّل في Audit Log فوراً
🔹 خارج النطاق: ⚠️ الرابط لا يُخزَّن في أي مكان في قاعدة البيانات — يُولَّد لحظياً فقط
🔹 دليل الإثبات: فتح الوثيقة + انتظار 6 دقائق + محاولة فتح نفس الرابط → رفض
🔹 فحصك المباشر: هذا الفحص إلزامي بنفسك — الانتظار 6 دقائق فعلاً قبل المحاولة الثانية
```

### 4.3 قبول/رفض طلب التحقق
```
🔹 النوع: كود
🔹 داخل النطاق:
   - قبول: تحديث is_verified = true على المستخدم + حالة الطلب إلى approved + Audit Log
   - رفض: حالة الطلب إلى rejected + سبب من قائمة الأسباب الموحَّدة (من موجز مرحلة 10) + Audit Log
🔹 دليل الإثبات: قبول طلب تجريبي → فتح تطبيق Flutter بنفس الحساب → badge "موثّق" يظهر فوراً
🔹 فحصك المباشر: رؤية الـ badge بعينك في التطبيق بعد القبول مباشرة
```
